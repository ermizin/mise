# Mise — дизайн-хэндоф

> Обновлено: 2026-09-01
> Статус: действующие решения и инварианты light-only Liquid Glass. Исторические батчи, старые QA-срезы и release SHA доступны в Git и не являются текущим планом.

## Источники истины

1. `PRODUCT.md` — пользовательский flow и продуктовые границы.
2. `app/globals.css` и UI-компоненты — фактические токены и состояния.
3. `tests/rendered-html.test.mjs`, `tests/ux-guarantees.test.mjs`, `tests/ux-audit-regressions.test.mjs` и `tests/motion-handoff.test.mjs` — защищённые визуальные и motion-инварианты.
4. `ROADMAP.md` — только действительно отложенные экраны и гипотезы.

Старые макеты и отчёты объясняют происхождение решений, но не имеют приоритета над текущим контрактом и тестами.

## Принятые решения

- Тема только светлая; PWA chrome не переключается по `prefers-color-scheme`.
- Светлая рампа `#FF8143 → #EE4C13` остаётся декоративным акцентом. Текстовые primary-действия используют контрастную `--accent-grad-aa`/`--button-grad`.
- Каталог — поверхность чтения и поиска. Карточку нельзя «добавить в партию» напрямую; избранное хранится локально и не влияет на автосборку.
- `Меньше мяса` не является быстрым фильтром. Вегетарианское и веганское направления требуют отдельного каталога и nutrition QA после пилота.
- КБЖУ обязательны для расчёта порций; режима «не считать КБЖУ» нет.
- `Не люблю` остаётся мягким исключением с явной возможностью показать варианты; `аллергия/мне нельзя` — жёсткий запрет.
- Ручной выбор меню существует внутри обязательного семишагового мастера и не заменяет автосборку по умолчанию.
- Карточка рецепта 14A не содержит pantry-состояния, статусов наличия и действий «есть/докупить».

## Визуальные инварианты

- `font-size` задаётся только токенами; числовой `font-weight` допустим лишь в двух `@font-face`. Литеральный `border-radius` остаётся только у квадратной отметки покупок; остальные радиусы берутся со шкалы `--r-*`.
- Минимальный кегль — 12 px. Текст, управляющие элементы и disabled-состояния должны сохранять проверяемый контраст.
- Новая тень не добавляется по месту: сначала переиспользуется существующий уровень или удаляется мёртвый. Тест ограничивает общее число `box-shadow` значением 48.
- Карточки каталога и мастера не создают собственный `backdrop-filter`; на экране остаётся не больше трёх крупных blur-слоёв.
- Узкие экраны не получают horizontal overflow; action bar, sheets и системные safe areas остаются достижимыми на 320 px.
- SVG-иконки не заменяются типографскими glyphs. Фото всегда ограничено своей media-рамкой и имеет fallback.

## Motion

- Геометрия движется через `transform`, состояние — через `opacity`; layout-анимация не должна вызывать горизонтальный скролл.
- Header и tab bar остаются визуально стабильными при переходах.
- Направление перехода соответствует порядку вкладок и экранов; повторные карточки получают короткий stagger, а не одновременный всплеск.
- `prefers-reduced-motion` сохраняет понятную смену состояния коротким fade без бесконечных skeleton-анимаций.

## Не считать текущей задачей

До отдельного решения после пилота не начинать тёмную тему, новые dietary-направления, полный экран кухни 12a, server-backed готовку партии 5b, pantry и крупный редизайн профиля. UX-наблюдение становится задачей только после воспроизведения на точном текущем HEAD и проверки на конфликт с `PRODUCT.md`.

## Проверка

```bash
pnpm run lint
pnpm test
```

Для UI-изменения дополнительно пройти затронутый flow на 320, 390 и desktop: проверить Back, клавиатуру/ARIA, safe areas, sheets, horizontal overflow, reduced motion и отсутствие ошибок консоли. Готовность production подтверждается только реальным публичным smoke-check по `AGENTS.md`.
