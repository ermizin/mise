
## 10. Редизайн C «Тонированное стекло» v2.2 (2026-10-17)

Владелец утвердил на дизайн-холсте направление C (26 экранов, палитра «терракота · мята · амбер», чернильные кнопки) и попросил внедрить его в приложение. Спецификация кита скопирована в репо: `REDESIGN_C_KIT.md` (§4 материалы и типографика, §7 решения владельца, §8 палитра). Холст: Claude Design «Mise — варианты редизайна», страница «C · Тонированное · полный набор v2.2».

**Слои стилей.** `app/globals.css` (токены и базовые поверхности) → `app/platform-layout.css` (раскладка `.app-workspace`, десктопный сайдбар) → `app/redesign-c.css` (общие переопределения v2.2) → `app/redesign-c-{week,cook,recipe,wizard,wizard-people,onboarding}.css` (экраны). Новые правила экранов живут в файлах пакетов; в `globals.css` — только токены.

**Что изменилось в токенах.** Гарнитура Wix Madefor (Display 700/800 для заголовков и чисел, Text 400/600/700; файлы в `public/fonts`, SIL OFL). Чернила `#2a1d14`, акцентный текст `#b3380a`, терракота `#c9400d` / плитка `#ffe3d2`, мята `#2e9c7c` / `#1c7359` / `#d8eee2`, амбер `rgba(224,162,75,.3)` / `#8f5a0c`. Радиусы 28/24/18/14, капсулы 999. Шкала кеглей 38/30/22/17/15/13/12. Стекло L1 — тонированный градиент с blur 26 (таб-бар, нижние панели, листы); карточки L2 — непрозрачные `rgba(255,247,240,.93)`. Фон — предразмытое фото блюда (`public/bg/*.jpg`) под тёплой заливкой с мятным пятном.

**Решения владельца, заменяющие §6.** Главные кнопки чернильные (`--button-grad: var(--ink-strong)`, `--button-fg: #fff1e6`): оранжевая рампа остаётся токеном для полос и акцентов, тесты обновлены. Тёмная тема отложена. Шкалы КБЖУ повторяют продуктовые (`norm-macro-tile`, `week-macro-row`). Цвет несёт смысл: мята — сделано/куплено/в плане, амбер — огонь/время/напоминания, терракота — план/дни/люди/числа.

**Экраны.** Онбординг (новая композиция «Готовка партиями» со сковородой, веером контейнеров и неделей из фото), мастер (пилюля «Шаг N из 7», полоса прогресса, стеклянная капсула действий 66 px, шаги 1–7, лист ограничений, «План готов!»), «Неделя» (капсула дней, «Сегодня», «Что дальше», «Баланс дня», чернильный круг «+» → лист «Следующий план», пустое и ошибочное состояния), готовка (карточка шага с фото, accessory таймера 58 px, взвешивание, раскладка по контейнерам), карточка рецепта 14A (фото-герой с переходом в размытие), каталог, покупки, профиль.

**Известные отступления.** Тексты, закреплённые тестами и контрактом, оставлены (например «Отправить ответ» на шагах 1–4, «Открыть план», «Цели и порции»). Календарь в карточке рецепта из плана сохранён по `PRODUCT.md`. На десктопе ≥ 1100 px сайдбар и раскладка из `platform-layout.css` не менялись; кольцо калорий там считает от дневной нормы, а колонки КБЖУ — от плана (нужно решение владельца).

### Проверка редизайна

Инструменты: `scripts/visual-check.mjs`, `scripts/lighthouse-baseline.mjs` и их общий клиент CDP `scripts/headless-chrome.mjs`. Нужны только Node и Google Chrome (путь переопределяется переменной `CHROME`), Lighthouse 13.5.0 скачивается через `npx`; результаты ложатся в git-игнорируемую папку `artifacts/`.

- `npm run visual:check -- --port 3184` — headless Chrome проходит онбординг → мастер из семи шагов → «Сохранить план» → «Открыть неделю» (в старых сборках «Открыть план») и снимает 20 экранов: онбординг 1–3, шаги 1–7, «План готов!», «Неделя», лист «Следующий план», шаг готовки, карточку рецепта, каталог, покупки и профиль на 390×844, неделю и каталог на 1280×900. Рядом с каждым PNG лежит JSON: горизонтальный скролл документа и экранных скроллеров, слои `backdrop-filter` (с `::before`/`::after`), минимальный кегль видимого текста, элементы за вьюпортом по горизонтали, ошибки консоли. Сводки — `summary.md`, `summary.json`, `glass.md` в `artifacts/visual/<время>/`. Если порт свободен, скрипт сам поднимает `npm run dev` (холодный старт 4–5 минут, нужен `pnpm` в PATH) и гасит его в конце. Пустые возраст, рост и вес на шаге людей обходчик заполняет значениями 30 лет, 178 см, 78 кг. План сохраняется в локальную D1, Метрика заблокирована, анимации выключены через `prefers-reduced-motion`. Код 1 — проход оборвался, часть экранов не снята.
- `npm run visual:check -- --glass` — то же плюс таблица «экран → элементы со стеклом» в консоли; код 1, если хотя бы на одном экране больше трёх слоёв.
- `npm run lighthouse:baseline` — `pnpm build` и `npm run start` текущей ветки, Lighthouse 13.5.0 в мобильной эмуляции, по три прогона двух страниц: главной глазами нового человека (онбординг) и `?tab=recipes` с пройденным онбордингом (каталог); медианы, HTML- и JSON-отчёты — в `artifacts/lighthouse/<время>-<метка>/`. `vinext start` отдаёт ответы без сжатия, а прод за Cloudflare их сжимает, поэтому локальную сборку скрипт меряет через brotli-прокси (`--raw` — без него). `-- --url https://mise.ermizinm.ru --label prod` меряет прод: запросы к `/api/analytics` и Метрике блокируются, воронка пилота не засоряется. `-- --compare <путь>/summary.json` добавляет таблицу «было → стало».

**Критерии перед выкладкой.** `visual:check --glass` проходит все 20 экранов с кодом 0: нет горизонтального скролла и элементов за вьюпортом, минимальный кегль не меньше 12 px, стекла не больше трёх слоёв. Lighthouse ветки против `main`, собранного тем же скриптом в соседнем worktree: доступность и best practices не ниже, CLS не выше 0,1 на обеих страницах, медиана LCP главной не выше 2,5 с, вес главной не больше чем на 15 % выше `main`.

**Откат после выкладки.** Предлагаемое правило: откатываем, если за 48 часов после выкладки доля «сохранил план» от «начал план» у новых устройств падает больше чем на треть относительно недели до выкладки, или приходит воспроизводимая жалоба на невозможность пройти основной flow (онбординг → мастер → сохранение → «Неделя», покупки, готовка). Доля считается по собственной аналитике (`ANALYTICS.md`): новые устройства — участники с `first_open` в окне, без устройств владельца и тестовых участников (исключения дашборда воронки); «начал план» — `plan_create_started`, «сохранил план» — `plan_created` того же участника. Цели Метрики `mise_plan_started` и `mise_plan_saved` — сверка для трафика из рекламы. Если за 48 часов план начали меньше 10 новых устройств, доля слишком шумная: окно продлевается до 7 дней, а до этого решает только критерий жалоб. Откат — переключение `/opt/mise/current` на сохранённый предыдущий релиз и перезапуск `mise.service` по процедуре из `AGENTS.md`, затем smoke-проверка `https://mise.ermizinm.ru`; прежний `sw.js` с кэшем `mise-shell-v4` при активации сам удаляет `mise-shell-v5`, кэш планов `mise-plan-v3` общий и сохраняется.
