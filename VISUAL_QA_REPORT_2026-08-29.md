# Mise — Visual QA Report (pre-release)

Дата: 2026-08-29 · ветка `codex/protein-policy-v19` · сборка: локальный `vinext dev`
Метод: headless Chrome 151 через CDP, реальные вьюпорты 320 / 375 / 390 / 768 / 1280 / 1440,
скриншоты + программные замеры DOM (getBoundingClientRect, computed styles, контраст).
Скриншоты: `.visual-qa/shots/`. Функциональные дефекты сознательно не рассматривались.

---

## 1. Visual release verdict

### NOT VISUALLY READY

Причина — не «много мелких шероховатостей», а два дефекта в главном сценарии, которые
любой первый пользователь увидит за первые 60 секунд:

1. **Шаг 6 из 7 визарда («Вид меню») сломан полностью**: текст карточек рендерится по одной
   букве в строку. Это не polish, это визуально нерабочий экран в обязательном шаге создания плана.
2. **На шаге 1 («Период») поле «Конец» уезжает за правый край экрана** на всех телефонных
   ширинах (≤430 px). Пользователь физически не видит дату окончания.

Кроме этого есть слой P1, который в сумме читается как «незаконченный MVP»: буква в аватаре
прижата к углу тайла, две разные primary-кнопки в одном флоу, `object-fit: cover` у фото
блюд не работает, `env(safe-area-inset-*)` мёртв из-за отсутствия `viewport-fit=cover`.

Хорошая новость: **дизайн-система в коде есть и она приличная** — токены радиусов, типографики,
хитбоксов, focus-ring `0 0 0 2px #fff, 0 0 0 4px #8f2708` реально применяется.
Почти все проблемы — это места, где компоненты обходят собственные токены,
а не отсутствие системы. Починка P0+P1 — это ~1 рабочий день, после чего продукт
переходит в состояние READY AFTER FIXES.

**Отдельно:** тёмной темы в приложении нет вообще (`prefers-color-scheme` и `data-theme`
в `globals.css` не встречаются). Пункт «light/dark» аудита неприменим — это не баг,
но это осознанное решение, которое стоит зафиксировать в PRODUCT.md.

## 2. P0 — Visual blockers

### VIS-001 · Карточки «Вид меню» рассыпаются по буквам
| | |
|---|---|
| Экран | Builder, шаг 3 из 7 «Вид меню» |
| Viewport | Все (320 → 1440) |
| Категория | **BUG** |
| Severity | **P0** |
| Screenshot | `shots/06a-style-top.png`, `shots/06b-style-mid.png` |
| Компонент | `app/globals.css:3120` (`.style-card`) + `app/page.tsx:10175` |

**Описание.** `.style-card` объявлен как `display: grid; grid-template-columns: 48px 1fr 30px`
(иконка / текст / радиокружок), но JSX рендерит только **два** ребёнка: `<div>` с текстом и `<i>`
с галочкой. Текстовый блок попадает в колонку шириной 48 px, галочка — в колонку `1fr`.

**Repro.** Главный экран → «Составить план» → Продолжить ×2 → шаг «Вид меню».

**Expected.** Заголовок и описание занимают основную ширину карточки, галочка справа.
**Actual.** Замер: `<h3>` шириной **48 px** при карточке 350 px. «Высо / кобе / лков / ое»,
описание «Больше / белка / для / сытост / и и / восста / новлен / ия». Кружок выбора висит
в середине карточки.

**Локальность.** Точечная: убрать первую колонку (`grid-template-columns: 1fr 30px`)
либо добавить `<span>` с иконкой. Одна строка CSS.

### VIS-005 · `object-fit: cover` у фото блюд не работает — кадр режется на 27 %
| | |
|---|---|
| Экран | Неделя → «Порции на день» |
| Viewport | Все |
| Категория | **BUG** |
| Severity | P1 |
| Screenshot | `shots/W2.png` |
| Компонент | `app/globals.css:5514` `.week-meal-thumb` / `:5523` `.week-meal-thumb img` |

**Описание.** Контейнер — `display: grid; place-items: center`. У центрированного grid-элемента
высота контейнера индефинитна, поэтому `height: 100%` резолвится в `auto`; `object-fit: cover`
никогда не срабатывает.
**Actual.** Замер всех трёх тамбов: контейнер `58×58`, `<img>` рендерится **58×74** →
`overflow: hidden` срезает **27 %** снизу. Для портретных фото блюдо уезжает из кадра,
для горизонтальных получится другой процент — кадрирование «плавает» от рецепта к рецепту.
**Expected.** Кадр 1:1, центрирование через `object-fit: cover`.
**Локальность.** Точечная: `place-items: stretch` или `.week-meal-thumb img { height: 100%; align-self: stretch; }`.

### VIS-006 · `env(safe-area-inset-*)` мёртв: нет `viewport-fit=cover`
| | |
|---|---|
| Экран | Всё приложение, установленный PWA на iPhone |
| Viewport | Мобильные с notch / home indicator |
| Категория | **BUG** |
| Severity | P1 |
| Компонент | `app/layout.tsx:30` `export const viewport` |

**Описание.** В CSS 18 мест аккуратно используют `env(safe-area-inset-*)`
(`.bottom-nav`, `.app-shell`, sticky-хедеры, FAB). Но в рендере мета-тег —
`<meta name="viewport" content="width=device-width, initial-scale=1">`, без `viewport-fit=cover`.
В iOS Safari/PWA без него все `env(safe-area-inset-*)` возвращают **0**.
**Actual.** `.bottom-nav { bottom: max(12px, env(...)) }` → фактически всегда 12 px,
плавающая навигация ложится на home indicator.
**Expected.** `viewport: { themeColor: ..., viewportFit: "cover" }`.
**Локальность.** Точечная: одна строка. Одновременно чинит верхние отступы под notch.

## Приложение: что проверено и оказалось в порядке

* **Focus-ring** — `0 0 0 2px #fff, 0 0 0 4px #8f2708` реально применяется к чипам, карточкам
  и кнопкам при табуляции; кольцо не обрезается контейнерами.
* **Радиусы** — 96 % значений из токенов, случайных 12/14/16/18 нет.
* **Типографическая шкала** — на реальных экранах используются ровно 32 / 19 / 15.5 / 15 / 13 / 12.5 / 12,
  посторонних размеров практически нет.
* **Горизонтальный оверфлоу** — на 375 / 390 / 768 / 1440 `scrollWidth === innerWidth`,
  ломается только 320 (каталог) и строка дат в визарде.
* **Высоты карточек в сетке** — при разной длине названий карточки сохраняют одинаковую высоту
  (ломается только выравнивание фото внутри них).
* **`prefers-reduced-motion` и `prefers-reduced-transparency`** — обработаны, для reduce-transparency
  есть полноценный непрозрачный набор поверхностей.
