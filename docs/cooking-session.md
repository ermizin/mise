# Сохранённая готовка партии 5b

Согласовано владельцем 2026-09-05. Последовательная готовка; параллельный общий таймлайн — отдельная задача.

## Состояние и восстановление

`app/use-cook-session.ts` сохраняет локальную оболочку синхронно перед обновлением экрана. В ней отдельно лежат подтверждённая revision, точный inFlight запрос с mutationId и более новая pending версия. Неопределённый результат повторяется с тем же mutationId; поздний ответ не затирает новые действия. После потери связи запросы повторяются при online/возврате на экран и с ограниченным backoff 1/2/5 секунд. HTTP-ошибка не превращается в успешное сохранение. Конфликт требует явного выбора локальной либо серверной версии.

`/api/cook-sessions` GET/PUT проверяет X-Mise-Client/X-Mise-Device, принадлежность плана и партии. Запись использует compare-and-swap revision и повторяемый mutationId. Идентификатор в БД — SHA-256 owner/plan/sessionKey. Ключ экрана зависит от рассчитанных продуктов, шагов, целей и выбранного способа приготовления. Хранятся отметки, текущий шаг, фаза cooking/portioning/complete, таймеры и веса.

Таймеры опираются на endsAt; пауза сохраняет остаток. Переход к другому шагу сохраняет работающий таймер. Истечение времени не подтверждает готовность еды. Wake Lock запрашивается по возможности и восстанавливается после возврата на экран.

## Offline и уведомления

Service worker кэширует посещённую оболочку, JS/CSS/шрифты и подходящие изображения. API готовки остаётся сетевым; его локальная очередь живёт на клиенте. Для отсутствующих JS/API/изображений HTML оболочка не подставляется. Офлайн-сценарий требует предварительно открыть приложение и загрузить план.

Фоновые уведомления требуют уже включённой добровольной Web Push-подписки того же устройства и плана. Пауза/завершение отменяют устаревшие задания. Id задания включает время окончания; повторный запуск не конфликтует с уже доставленным таймером. Существующая lease сохраняется при повторном сохранении. Планировщик проверяет актуальное состояние перед доставкой и отбрасывает таймеры, просроченные больше 5 минут.

Существующий планировщик работает раз в минуту: это не точный системный будильник. Доставка зависит от сети и платформы; при закрытом приложении без сети сигнал не гарантируется. Реальная доставка на заблокированный iPhone в этом инкременте не проверена. Локально проверены создание/отмена/повтор заданий в D1, сохранение lease, отдельные notification tags и fallback без разрешения.

## Продукты и раскладка

Используются общие рассчитанные количества `cookingAmounts`, включая единый расход cooking fat. Узкая структурированная связь инструкции с ингредиентом показывает только его количество из отмеренной партии. Legacy-разметка, повторяющая весь состав на каждом шаге, не выдаётся за точную: панель явно сообщает, что показывает продукты всего блюда. Расход одного ингредиента между несколькими шагами не выдумывается. Полная редакционная разметка таких шагов остаётся ограничением исходных данных.

После последнего шага открывается существующая раскладка по фактическим весам; её черновик сохраняется вместе с сессией. Подтверждение партии и `cooking_confirmed` остаются после заполнения и сохранения раскладки.
