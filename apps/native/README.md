# Mise для iPhone

Нативный клиент на Expo SDK 57, React Native и Expo Router. Он запускается как приложение iOS, без WebView. Встроенный проверенный каталог, фотографии и правила расчёта порций позволяют создать план, открыть рецепты, отмечать покупки и готовку без сети. При подключении приложение обновляет каталог и синхронизирует план через API Mise.

## Запуск

Требуются Node 22+, pnpm и Xcode с iOS Simulator. Из корня репозитория:

```sh
pnpm install
pnpm --filter @mise/native start
```

В меню Expo нажмите `i` для iOS Simulator. Для собственного iPhone используйте development build (`pnpm --filter @mise/native ios`) и подпись Apple Developer. Expo Go может не отражать поведение системных уведомлений и SecureStore полностью.

API по умолчанию: `https://mise.ermizinm.ru`. Для другого сервера создайте `apps/native/.env.local` по примеру `.env.example` и укажите `EXPO_PUBLIC_API_URL`. Адрес в development build должен быть доступен с самого iPhone, а не только с Mac.

## Проверка

Для воспроизводимой установки используйте `pnpm install --frozen-lockfile`. В `patches/` зафиксированы три узких исправления зависимостей для Xcode 26.3: UTF-8 пути Hermes, экранирование пробелов в скрипте Expo Constants и совместимость Expo Modules JSI со Swift 6.2. Они применяются автоматически через `pnpm-workspace.yaml`; ручные изменения `node_modules` не требуются. При обновлении соответствующих пакетов патчи нужно пересмотреть и повторить нативную сборку. Для CocoaPods используйте UTF-8 окружение (`LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install`).

Локальный config plugin `plugins/with-quoted-ios-bundle.cjs` дополнительно экранирует путь финального React Native bundle-скрипта при каждом Expo prebuild. Это нужно для рабочих каталогов с пробелами; преобразование идемпотентно и покрыто отдельным тестом.

```sh
pnpm --filter @mise/native typecheck
pnpm --filter @mise/native test
cd apps/native && EXPO_NO_TELEMETRY=1 npx expo install --check
```

Каталог и локальные фотографии обновляются из редакционного runtime-каталога командой `pnpm mobile:catalog:refresh` из корня. После обновления повторите тесты и iOS export; проверяйте, что число рецептов, photo checksum и schemaVersion совпадают. Сгенерированные `assets/mobile-bootstrap.json` и `src/generated/recipe-assets.ts` входят в приложение. Текущий встроенный каталог содержит 250 разрешённых для приложения рецептов, включая направление «Простые». Внешняя сеть нужна только для обновления каталога и синхронизации.

На шаге «Когда готовим?» пользователь отмечает доступную технику и посуду. Новые планы используют только исходный способ рецепта, если для него есть вся нужная утварь. Выбирать между «обычным способом», мультиваркой или аэрогрилем отдельно не требуется: дополнительные старые варианты остаются только для совместимости с ранее сохранёнными web-планами.

Иконка `assets/icon.png` — непрозрачный PNG 1024×1024 из существующего фирменного исходника Mise, без новых сторонних материалов. Воспроизводится командой `swift scripts/generate-app-icons.swift --native --output apps/native/assets` из корня; детерминизм и PNG-параметры проверяет `tests/app-icon-assets.test.mjs`. Фотографии переиспользуются из существующего каталога: новые изображения этим изменением не добавляются.

## Сборка для iPhone и TestFlight

Для локальной установки на собственный iPhone откройте `apps/native/ios/Mise.xcworkspace` (создаётся `pnpm --filter @mise/native exec expo prebuild --platform ios`). В Xcode → Settings → Accounts добавьте свой Apple ID; в Mise → Signing & Capabilities выберите свою Team. Подключите разблокированный iPhone, подтвердите доверие и включите Developer Mode, если iOS попросит. Выберите iPhone как цель запуска и конфигурацию **Release**: она содержит JavaScript и фотографии внутри приложения и не требует работающего Metro на Mac. Неподписанная сборка подтверждает компиляцию, но сама по себе не устанавливается на iPhone.

Проверка на устройстве выполняется владельцем. Начните с авиарежима **до первого открытия**: пройдите онбординг, создайте план, замените одно блюдо, сохраните. Откройте фотографии рецептов, покупки, готовку и раскладку; отметьте покупку и порцию. Полностью закройте и снова откройте приложение — план и отметки должны сохраниться. Затем отдельно проверьте локальные напоминания с разрешением и с отказом. После возвращения сети убедитесь, что синхронизация не откатила изменения. Не называйте эти сценарии проверенными до фактического прохождения на устройстве.

Настройте проект EAS и Apple Developer для bundle ID `ru.ermizin.mise` (окончательное значение подтвердить в App Store Connect). Затем из `apps/native`:

```sh
npx eas-cli build --platform ios --profile development
npx eas-cli build --platform ios --profile production
npx eas-cli submit --platform ios
```

Профили сборки находятся в `eas.json`. До TestFlight нужны проверка на реальном iPhone, финальные скриншоты, опубликованная политика конфиденциальности, App Store Connect metadata и подтверждённый Apple team. Команды выше не означают, что приложение уже опубликовано.

## Данные и напоминания

UUID устройства хранится в iOS Keychain через SecureStore. План, каталог, черновик и очередь синхронизации хранятся в SQLite. Изменения локально сохраняются первыми, затем отправляются в `/api/plans`; обновление каталога идёт через `/api/mobile/bootstrap`. Уведомления локальные: разрешение iOS запрашивается только после просмотра расписания и нажатия «Включить напоминания» в профиле. Удаление плана также записывается в очередь и синхронизируется при следующем подключении.

КБЖУ и сроки хранения являются ориентирами. Жёсткие исключения выбираются из кодов аллергенов, совпадающих с правилами общего генератора. Следы аллергенов в конкретной упаковке приложение не может проверить.
