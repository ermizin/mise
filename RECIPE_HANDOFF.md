# Mise — каталог и Recipe Engine

> Обновлено: 2026-09-05
> Контракт: [`PRODUCT.md`](PRODUCT.md) v3.9.0
> Статус: владелец 2026-09-05 снял functional freeze после релиза. Согласованные изменения каталога и движка разрешены; текущие числа и готовность всегда перепроверяются по machine-readable audit точного HEAD.

## 1. Текущий срез

Исключение владельца от 2026-09-05: пакет «Простые» — 25 разработок Mise со сгенерированными изображениями и 25 адаптаций с фото источников. Исходный корпус не перезаписывается. Новые входные карточки — `data/simple-recipes.json`, медиа — `data/simple-recipe-images.json`, сборщик — `scripts/build-simple-recipe-catalog.mjs`, проекция — отдельное поле `simpleRecipes` общего runtime-файла. Новые записи входят в общий реестр сохранения планов. Публичные права на новые source-фото проверяются перед выпуском координатором.

- Зафиксированный корпус: 255 самостоятельных карточек — 221 карточка из 217 исходных страниц и отдельно одобренные 34 карточки из 32 источников «Простые и домашние».
- `data/recipe-release-audit.json`: 202 `ready`, 0 `review_required`, 53 `blocked` после повторной поварской вычитки. В generated runtime-каталог попадают только `ready`.
- Общий массив приложения содержит дополнительные legacy-записи; его размер нельзя называть размером audited runtime-каталога. Любое число подписывается контекстом.
- Минимум для автосборки — 200 audit-gated карточек. Текущий каталог его проходит; новые источники требуют конкретного продуктового решения.

Снятие заморозки разрешает согласованное развитие, но не отменяет raw provenance, редакционные gates, детерминированный пересчёт и проверку exact HEAD перед выпуском. Выбор утвари и минимум 50 рецептов суммарно для мультиварки/аэрогриля отдельно заказаны владельцем 2026-09-05.

## 2. Источники истины

| Слой | Назначение |
| --- | --- |
| raw candidate corpora | Неизменяемое доказательство исходных страниц и значений. |
| `data/mealprep-owner-decisions.json` | Подтверждённые владельцем замены и исключения. |
| `data/recipe-proofread-policy.json` | Поварская вычитка: состав, шаги, температуры, хранение, порции, локализация и карантин. |
| `data/simple-home-runtime-approval.json` | Точный одобренный состав пакета «Простые и домашние». |
| `data/recipe-image-manifest.json` | Связь карточки, source URL, локального фото, MIME и checksum. |
| `data/recipe-release-audit.json` | Единственный источник текущего verdict. |
| `data/recipe-equipment.json` | Адресная разметка необходимой утвари и способов приготовления; разогрев не считается отдельным способом. |
| `data/recipe-runtime-catalog.json` | Generated runtime-проекция; руками не редактируется. |
| `data/recipe-runtime-integration-audit.json` | Доказательство полноты runtime-проекции и покрытия. |
| `data/plan-recipe-registry.json` | Generated список доступных плану рецептов, слотов, аллергенов и хранения; совпадает с production-каталогом приложения. |

Owner choices применяются overlay-слоем, затем пересобираются release audit, runtime catalog и integration audit. Raw corpus, IDs, порядок, provenance и source nutrition сохраняются. В runtime нет вызовов OpenAI, Anthropic или другой LLM: солвер и покупки детерминированы.

## 3. Неподвижные редакционные правила

- Выбран карточный путь B. Модульный конструктор — только post-pilot гипотеза и требует изменения `PRODUCT.md`.
- Качество определяется проверкой, а не происхождением карточки. Инструкции пишутся заново по фактам источника; авторский текст не копируется.
- Локализация проверяется по привычности формата, доступности продуктов и употреблению после хранения. Нишевый продукт — сигнал, а не автоматический запрет.
- КБЖУ привязываются к конкретным записям USDA FoodData Central с формой продукта и датой проверки. Для брендозависимого продукта используется подтверждённый профиль и остаётся напоминание сверить этикетку.
- Консервативный ориентир холодильного хранения — 3–4 суток при `≤4 °C`; более длинная партия требует подтверждённой заморозки. Срок нельзя завышать ради покрытия.
- Runtime-карточка обязана иметь исполнимый состав и шаги, recalculated nutrition, хранение/заморозку/разморозку, packing data, complete Recipe Family и локальное фото конкретного источника. Отдельная packing-инструкция в UI не дублируется. Hotlink, AI-фото и несвязанный сток запрещены.
- Техническая целостность фото не доказывает право публикации. Для любого нового или изменённого фото нужен записанный release-rights verdict.

## 4. Зафиксированные решения по данным

- Говяжий фарш использует baseline 85/15; старые 90/10 и 93/7 остаются только входными aliases. Фрикадельки Обломова используют готовый куриный фарш, а не бедро и мясорубку.
- Рис всегда означает сухую крупу. Для импортированной массы готового риса нужен доказуемый коэффициент; иначе карточка блокируется. Политика охватывает 29 карточек: основной коэффициент `0,4`, у `tmpm-26660` — `0,48`. Runtime использует `rice_raw` и явный шаг варки.
- Мирин сохраняется; допустимая альтернатива — вода с сахаром 3:1 и несколько капель рисового уксуса по желанию.
- Белковая смесь вафли раскрыта на сывороточный и казеиновый протеин, овсяную муку, кукурузный крахмал и разрыхлитель.
- Тефтели из индейки с гречкой исключены решением владельца.
- Измеренные специи и технологические компоненты сохраняют source-derived количество на базовую порцию и детерминированно масштабируются; только исходно неизмеренные позиции получают текстовый статус.
- Сыр и паста считаются в граммах; бульон — в миллилитрах при `1 г ≈ 1 мл`; `piece` используется только для реально штучного продукта с canonical mass.
- Покупки агрегируются по canonical identity и единице. Legacy alias и canonical ID одного продукта не должны создавать дубль.

## 5. Инварианты Recipe Engine

- Калорийный коридор порции — `0.90T…1.05T`; фиксированные доли слотов — `25/10/30/10/25` без перенормировки.
- Meal protein share — цель ранжирования, а не жёсткий фильтр. Жёстким остаётся минимальный белок конкретной Recipe Family; дневная цель проверяется по меню.
- Структурные штучные ингредиенты округляются целыми шагами.
- `fat_cooking` фиксируется на выбранную готовку, учитывается один раз и распределяется между порциями только для КБЖУ; съедобный `fat` может масштабироваться.
- Runtime показывает один общий `cookingAmounts`; автоматические cooking splits и фильтр по вместимости посуды удалены. Геометрия может оставаться audit metadata, но способ готовки выбирает человек.
- Персональные solves — предложения для состава партии. После агрегации все КБЖУ и количества в порции пересчитываются из единой доли `cookingAmounts`; повторное объединение несовместимых персональных назначений запрещено. Структурное округление выполняется для готовки, дробная доля внутри готового блюда допустима.
- Подтверждённые съедобные жиры соусов, пюре и теста получают `fat` через адресные overrides с recipe/ingredient/instruction evidence в `domain/recipe-engine.ts`. Непроверенные случаи сохраняют прежнюю роль; полная поварская оценка гибких пропорций остаётся отдельной задачей.
- Сохранение на сервере проверяет доступность рецепта по тому же production-каталогу, слот, хранение, жёсткие исключения и полное однократное покрытие людей назначениями. Legacy-план без поля назначений использует полный `selections`; явно заданные неполные назначения отклоняются.
- Источник, адаптация и рассчитанные значения хранятся раздельно. Materially changed recipe не наследует source macros как собственные.

## 6. Что остаётся после пилота

Без отдельного решения владельца не реализовывать:

- per-family overrides поверх общих `bounds()`;
- упаковочный шаг фабричных соусов;
- satellite-модуль для добора калорий вместо растягивания блюда;
- модульный конструктор и новые источники.

## 7. Release gates

После изменения overlay, canonical mapping или proofread policy:

```bash
pnpm recipes:audit:release:write
pnpm recipes:runtime:refresh
node scripts/audit-recipe-runtime-integration.mjs --output data/recipe-runtime-integration-audit.json
pnpm test
```

Проверить воспроизводимость generated-файлов и отсутствие в runtime карточек с verdict не `ready`, missing mapping/amount/unit, несверенными КБЖУ, дублирующими canonical ingredients, готовым рисом без пересчёта, конфликтующим хранением, неисполнимыми шагами, отсутствующим локальным фото, незафиксированным release-rights verdict или gap по slot × batch days. Generated JSON при конфликте пересобирается, а не разрешается вручную.

Для выпуска действуют Git/VPS-gates из `AGENTS.md`: чистый exact HEAD, полный lint/test/build, резервная копия, rollback и проверка реального публичного flow.
